# DAMDesk v0.1.0-preview — Release Notes

> First public preview. The installer is intentionally **lite**: it ships only what semantic
> search needs. Everything else is an explicit, reviewable download.

## What this is

DAMDesk is a **local-first desktop DAM where industry processing flows are installable plugins** —
your library stays on your disk; import, tagging, dedup, and search run in one desktop process.

## The plugin mechanism (the part DAMDesk exists for)

1. **Plugins are subprocesses, not libraries.** Each pack's entrypoint is spawned as a child
   process speaking line-delimited JSON-RPC 2.0 over stdio — a crash, a hang, or a stray
   `print()` in a plugin cannot touch the host or your library.
2. **Capability gateway.** Plugins have no direct network or filesystem access; every request goes
   through a whitelisted gateway, and results are three-state (`pass` / `fail` / `undetermined`)
   with the exact plugin build recorded on every row.
3. **Pack lifecycle.** A plugin ships as a self-contained `.dampack` archive (manifest + entrypoint
   + dependencies inside the pack) — install, switch, and roll back like a package, never fighting
   another pack's dependencies. An executable conformance spec keeps all of this honest.

## Models: what's inside, what's optional

- **Built in — the retrieval tower.** `siglip2-base-p224-onnx` (image + text towers, ONNX,
  785 MB) is bundled with the installer. Search works out of the box, offline, zero configuration.
- **Optional enhancements — 504 MB total, not bundled.** Subject segmentation (u2net), OCR
  (PP-OCRv6 medium det/rec), super-resolution (RealESRGAN x4v3), and inpainting (LaMa) download
  from inside the app (Settings → Models → *Download all*, HuggingFace primary → COS mirror), or
  via *Import from folder*, or by unzipping `damdesk-models-extras-v1.zip` into your models
  directory. The app tells you exactly what is missing and why until then.
- **Bring your own — DINOv3 (duplicate detection).** DINOv3 weights are licensed by Meta and are
  **not redistributable**, so they are never bundled or auto-downloaded. If you want duplicate
  detection, obtain the ONNX export yourself and drop the two files into
  `<data>/models/dinov3-vits16-onnx/`; until then the app reports dedup as unavailable rather
  than pretending.

## Known limitations

- Duplicate detection stays unavailable until you provide DINOv3 yourself (see above) — the app
  surfaces this honestly instead of silently degrading.
- In-app model downloads land next to the built-in tower inside the install directory; install to
  a user-writable location (the default per-user install path satisfies this).
- Until the public mirror bucket policy is finalized, some networks may not reach the COS mirror;
  the HF source and *Import from folder* / zip remain unaffected.
- The macOS build is ad-hoc signed: first launch requires right-click → Open (Gatekeeper).
- First-run indexing performance is CPU-bound; large libraries should let the initial embed pass
  finish before judging search latency.

# DAMDesk 产品说明

> 版本：0.1.0（main 基线 2026-10-20）· 许可证：AGPL-3.0 · 形态：桌面单机（macOS / Windows）+ 自托管容器

## 1. 这是什么

DAMDesk 是**以多模态 AI 为核心、以图片工作流为引擎、以行业解决方案包为扩展方式的通用图片处理与质量治理平台**。

英文 tagline：**AI-Powered Image Operations**

一句话：从图片管理到智能打标、规则校验、批量处理与标准化交付。

五个对外能力：

```
AI Tagging          多模态模型打标，模板任务 + 自定义任务，两段式人工确认
Quality Validation  规则引擎校验（rules.yaml），三态判定 + 置信度 + 人工复核
Batch Processing    队列化批处理：打标、修复、变换、去重、导出，断点续跑
Processing Plugins  一个能力 = 一个可安装插件，换行业 = 换插件，不改宿主代码
Automated Delivery  导出目录/zip + manifest + 判定报告，随交付带证据
```

与「相册 / 回忆保存」型图库工具的差异：那类工具解决"把照片存起来并想起来"，DAMDesk 解决"生产资料治理"——
图片是原材料，要能被打标、被校验、被批量处理、被标准化交付。

## 2. 谁能用

- 电商：商品图批量打标（品类/规格/材质）、白底/主图合规校验、标准化导出给渠道
- 制造业：型号/规格归档，尺寸与包装属性统计，交付前一致性检查
- 房产/中介：房源码统一命名、室内/室外分类、失联文件记录
- 设计/品牌：素材分级（色标 / 自定义质量标签）、重复素材清理、按活动渠道分发
- 个人/小团队：本地图库 + AI 打标 + 去重，数据不出本机，零运维

边界：单用户桌面产品（多租户协作、审批签核、计费属于云 DAM 形态，不在本仓库范围）。

## 3. 核心概念

### 3.1 统一标签（tag）

- 打标结果**全部输出数组**，每个值扇出成一条独立标签；`tag` 表只有 `value` 一列，唯一键 `(assetId, value)`。
- 结构化属性**拍平成字符串**：`任务名-值`，例如 `材质-棉`、`场景-室内`。
- 值必须**离散**：连续量先分桶（`尺寸-4k`、`年份-2024`），不做数值范围查询。
- 值内多词用下划线：`MacBook_Pro_13寸`、`尺寸-滚筒_10KG`（`-` 只分隔层级，`_` 只连接段内词）。
- 支持**多级值，深度 ≤3**：`尺寸-滚筒-10KG`。只有叶子落库，父级（`尺寸`、`尺寸-滚筒`）是视图节点，
  计数由前缀聚合得出，不建层级表。

为什么这样做：行业定制属性 = 新任务 = 新标签前缀，**零 schema 变更**；750 万行实测单值筛选 1.3ms、
前缀分组 191ms、三标签交叉 124ms（SQLite 单机足够）。代价：数值聚合（均值/求和）做不了，放导出层。

### 3.2 两段式打标确认

任务跑完不等于标签入库：结果先进 `tag_proposal`（提案），在**待确认**页逐条/批量确认才写正式表，
人工修改优先于模型输出。目的：模型质量不可全信，人要对库里的标签负责。

### 3.3 资产标记两件套（正交，不合并）

| 标记 | 语义 | 写入方 |
|---|---|---|
| 拒选 reject | 「这张不要」 | 人工（检查器 / 工具条 / X 键） |
| 色标 colorLabel | 团队自赋分类 | 人工（检查器） |

标签里的 `score` 是模型置信度，与人工判断不是一回事，永不覆盖人工标记。

质量分级（KI-11 裁决，2026-10-20）：产品**不做**星级评分（旧库已打星的数据保留在
`starRating` 列与导出 manifest 里可导出，但界面无任何入口）；各行业用自己的质量打分逻辑，
用定制标签表达（如 `质量-优`、`瑕疵-轻微`）。

## 4. 主流程（怎么用）

```
① 导入        拖文件夹 / 选目录 → 库根登记 → 缩略图与向量生成
② 打标        建任务（模板或自定义，写清输出格式）→ 入队 → 模型跑 → 待确认
③ 确认        TagReview 逐条/批量确认入库（可改值），标签即进主表
④ 找图        目录树 / 标签 / 未打标 / 失联 / 无法预览 多维叠加筛选
               文搜图（自然语言）、以图搜图（找相似）、按条件浏览
⑤ 校验        选中图片「送去处理 →」选能力 + 方案 → 跑一次 job
               结果一律在任务中心看（L1 列表 → L2 这次执行 → L3 图级明细，可就地改判）
⑥ 处理        修复（超分/抠图/inpaint）、变换（尺寸/格式/水印）、去重（pHash + 向量）；产物导出在 L2
⑦ 导出        选范围（筛选/选择集）→ 目标目录 + manifest → 任务中心看进度
```

关键交互事实：

- 筛选条件与 URL 同步（刷新/深链/后退都复现同一次筛选），筛选芯片可逐个摘除。
- 搜索页：有 query 走向量检索；**只有过滤条件（标签/目录/扩展名）也能浏览**，计数与图库同口径。
- 标签输入带**前缀候选**（按 `-` 前 key 分组、显示计数、键盘 ↑↓/Enter/Esc）。
- **图库 / 搜索 / 检查器是纯资产域**：只有固有属性与标签/色标/拒选/目录，没有任何判定或 job 概念；
  判定/处理结果、人工改判、按结果导出全部在任务中心（跨 job 的「待人工看」= 任务中心工具栏的低频弹窗）。
- 命令面板 `Ctrl/⌘+K`：跳页面、跑动作、找筛选。
- 弹窗统一三路关闭：ESC / ✕ / 点遮罩；页面级与 Drawer 级载体按信息量划分。

## 5. 处理插件（Processing Plugins）

**一个能力 = 一个插件；行业是插件可带的属性（domain）**：判定/修复、成像处理（抠图/超分/水印/换背景）、
规则、词表、报告元数据、流程代码全在插件包里，插件自带它需要的全部信息，不依赖宿主里另挂一套
「行业规则」。装插件即可用（判定或处理由包的 `outputs` 声明，协议 v2.0 单执行动词 `run`），没有
「先装行业包再切引擎」两步。

```
manifest.json          插件身份（id / 版本 / 需要的能力 / 入口）
plugin/                流程代码（判定步数、顺序、分支、修复策略都在这里）
resources/rules.json   规则清单 + 报告列名 + 低置信度阈值（界面规则列表/报告都读它）
resources/taxonomy.json 受控词表（打标只往这些值里落）
```

插件内可以预置 key 与受控词表（如电商：品类/规格/材质），但界面不做行业分支——
显示顺序一律按计数，行业差异只体现为"这个插件预置了哪些 key、有哪些值可选"。

## 6. 部署与存储

| 形态 | 说明 |
|---|---|
| 桌面（推荐） | Tauri 壳 + 内嵌 axum（127.0.0.1 随机端口 + 一次性 token）+ React 前端；macOS Apple Silicon / Windows x64 安装包 |
| 自托管容器 | 同一前端 + 同一后端，浏览器访问；**发布镜像同样编入 local-infer**（`deploy/Dockerfile` 显式 `--features local-infer`），与桌面版能力面对齐，官方 5 包都可装；模型不内置，走 `DAM_WEB_MODELS_ROOT` 挂卷或 app 内下载，embedding 也可改走远程 provider |

- 数据库：SQLite（`dam.db`，含 FTS/向量扩展），全部元数据与判定记录本地。
- 文件：`appData` 固定项（缩略图、向量、标签、判定报告）+ 库根引用；支持 reference（引用原位置）与 copy-in（迁入库）。
- 推理：本地 ONNX（SigLIP2 文/图向量、DINOv3 判重塔、U2Net 抠图、PP-OCRv6 检测+识别、Real-ESRGAN 超分）；
  打标调用任意 OpenAI 兼容多模态模型（dam-ai / zhipu / dashscope / Ollama / 自定义）。
- 断网可用：本地库、浏览、筛选、标签、去重照常；只有需要远程模型的打标会报可读错误。

内置模型（随安装包，共约 1.1 GB）：SigLIP2-base（text 539M + vision 177M）、DINOv3 ViT-S/16（82M）、
U2Net（168M）、PP-OCRv6-medium det（59M）+ rec（73M）+ 字典、Real-ESRGAN x4v3（4.6M）。
Inpainting（LaMa）不内置，按需下载。

## 7. 性能与规模

- 标签：50 万资产 × 15 标签 = 750 万行，单值筛选 1.3ms、双标签交叉 86ms、三标签 124ms。
- 标签候选：走字典表（distinct 值 + 计数）前缀范围扫描，微秒级，与总行数无关。
- 打标队列：64/批，断点续跑，失败按资产记 attempts + lastError + 重试。
- 导出：目录/zip + manifest（含判定与来源），进度在任务中心。

## 8. 已知限制（不要当已实现宣传）

1. 数值聚合（均值、求和、范围比较）不做；标签是离散字符串。
2. 标签 key（任务名）改名不追溯已落标签前缀，只影响新扇出。
3. 合规反馈闭环（C6）未做；完整性报告页 / `dam.db` 备份 / XMP sidecar 三项未排期。
4. 标签总览页（`/tags`）与统一候选组件在 plan 阶段，尚未实现。
5. macOS 安装包未签名/未公证，首次打开需右键 → 打开。

## 9. 系统要求

```
macOS     14+（Apple Silicon 构建），首次启动需允许本地网络访问
Windows   10/11 x64（需 WebView2 运行时，安装包自带引导）
内存      8 GB 起（16 GB 建议，批量处理/向量索引更稳）
磁盘      安装包 1.1 GB + 库容量（缩略图与向量约占原图 5–10%）
网络      仅远程打标需要；其余全离线
```

## 10. 快速上手（10 分钟）

1. 启动 → 首启向导选库根（图片所在目录）。
2. 导入一个目录，等缩略图与向量完成（任务中心可见）。
3. 建一个打标任务（模板选"商品属性"，或自定义 prompt 声明输出数组格式）。
4. 跑完去「待确认」批量确认，标签即入库。
5. 回图库点标签筛选；或搜索页输入自然语言试文搜图。
6. 装一个处理插件（如电商主图处理插件）跑合规，看判定报告。
7. 框选一批图导出，检查 manifest 与报告是否随交付。

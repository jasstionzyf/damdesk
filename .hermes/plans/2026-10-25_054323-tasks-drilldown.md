# 处理记录页层级化改造：统一 job 列表 → 本次结果 → 图级明细（三级下钻）

> 用户裁决方向（2026-10-25）：处理记录对人工不友好，改为**层级显示**——
> L1 先显示后台 job 列表与状态 → L2 点击某个 job 显示该次执行结果 → L3 需要看图时弹出图列表结果。
> **补充裁决（同日）：所有任务抽象成 job，仅类型不同**（打标 / 导入 / 导出 / 去重 / 检查 / 处理）——
> 不同类型对应的 job 结果界面不同，但**统一走类似流程、共用相关界面**。裁决正文回写
> `damdesk-product/references/job-task-semantics.md`（2026-10-25 统一 Job 抽象节）。
> 本 plan 只规划不执行；实施前先改 `damdesk-flows`（流程先行）。
> 问题已录 known-issues KI-37。

## 1. 问题（现状代码事实）

`/tasks` 单页纵向四段堆叠（`web/src/pages/Tasks.tsx`）：

| 分区 | 问题 |
|---|---|
| 后台工作（TaskList） | 与「检查与处理结果」两套列表、两套数据源，用户要分清「哪段是我要的」 |
| 检查与处理结果（JobResults） | 选中即内联展开大表格，列表与明细抢同一屏；纯文字无缩略图；筛选只有 全部/检查/处理，无 未通过/待人工看 |
| 导入批次 | 与「处理」语义无关却占一屏 |
| 导出记录 | 同上，且页头文案「只保留最近一次」误伤判定结果的信任（判定行后端永久保留） |

具体不友好五点：
1. job 摘要行只有执行语义（成功/失败/跳过/耗时，`ComplianceJobs.tsx:9`），没有判定分布（通过 X / 未过 Y / 待看 Z）。
2. 结果表纯文字（`JobResults.tsx:362`，limit 500），判的是图却没有图。
3. 复核路径断：「去复核未判定的图 →」跳合规页复核队列，离开本页丢上下文。
4. 身份抽象：「第 N 次 · #runId」主导，人话身份（时间+能力名+方案+张数）弱。
5. 保留口径吓人（见上表）。

根子上还有第六点：**同一件事（一次执行）有两套概念**——后台工作走 TaskList，检查/处理走
compliance run，界面被迫分两段。「统一 job 抽象」裁决直接消掉这个二元性。

## 2. 目标形态：统一 job + 三级下钻

```
L1  job 列表（页面主体，时间倒序，正在跑的置顶带进度）
    所有类型一个列表：打标 / 导入 / 导出 / 去重 / 检查 / 处理
    行 = [类型图标+状态点] 时间 · 标题(能力名/任务名) · 方案(如有) · N 张 · 结果摘要 · 耗时
    摘要按类型：检查=通过 X/未过 Y/待看 Z；处理/导入/打标=成功/失败/跳过；导出=N 张+目标
    快捷过滤：全部 / 进行中 / 检查 / 处理 / 导入导出 / 打标

L2  点行 → 该次结果（页内展开，不跳页；视图按 job 类型分化）
    检查类：判定分布卡（通过/未过/待看，可点）+ 结果表（列 = result_columns）
            表顶部「只看 未通过 / 待人工看」过滤 chip
    处理类：成功/失败/跳过 + 产物缩略图行（勾选导出，沿用 PROC-RES-2）
    导入类：批次明细 / 失败清单 / 只重跑失败项（原 ImportBatches 行内能力）
    导出类：报告 + 打开文件夹 + 跳过/失败明细（原 ExportRecord 能力）
    打标类：完成态 + 进「待确认」入口（F4 的确认仍归 /tag-review，链接过去）
    出口：去图级明细（L3）｜类型各自的动作（重试/取消/导出/打开）

L3  点缩略图/看这批图 → Dialog 弹出图级结果
    缩略图网格 + 每图结果角标 + 点单图进检查器（复用 InspectorDock：大图 + 证据 + 人工改判/标记）
    关闭即回 L2，选中与滚动位置不丢
```

**共用与分化的边界**（统一 job 抽象的落法）：
- **共用**：L1 列表骨架与行组件、状态点/进度卡、过滤框架、L2 展开容器、L3 Dialog 容器、
  时间/耗时/计数格式化、空态与错误文案骨架。抽 `JobRow / JobStatusBadge / JobProgressCard /
  JobResultShell / JobImageListDialog` 一套共用组件。
- **分化**：只有 L2/L3 的**结果内容区**按 type 注册（检查=判定表+复核、处理=产物、导入=失败清单、
  导出=报告、打标=待确认入口）。新类型 = 新增一个结果视图注册项，L1/L3 与流程骨架零改动。

裁决依据（不翻案，只落位）：
- 「一个能力只归一个区域」「跑与看结果在任务中心」→ L1-L3 全在 /tasks 内闭环。
- 命名表（任务 Job=处理记录「每次批量处理的进度和结果」）——统一 job 抽象是该定义的全类型展开，一致不冲突。
- 分层载体：L2 页内展开；L3 图网格 Dialog + 单图走检查器（低频深度动作，Dialog 合法）。
- 「全部图库」等既有红线不动；处理类不画审核面照旧。
